# 后续方案：电话语音 → 本地转文字 → 飞书 Webhook

设计时间：2026-11-23。**本文件是下一阶段方案，不代表 V0.4.6 已实现语音转写。**

## 1. 目标和约束

- 保留现有 Android vivo S9e + Mac Apple Silicon + ADB 实时 PCM 架构；电话语音识别运行在 Mac，本地完成，不购买云端语音 API，不假设 ChatGPT Plus 能供程序调用语音接口。
- 严格区分三种声音源：① 运营商电话对方下行；② 本机 Mac 麦克风真实上行；③ BlackHole 16ch 中可能含其它系统声音的 ChatGPT 回复。**不得把③自动当作真人说话**。
- 先实现逐字转写文本，再支持「已确认的转写片段」自动发送到已配置的飞书私人群，可选择延迟批量通知；完整原始音频默认不落盘。
- 每次通话开始需要通话双方知情同意；首次启用语音转写需清楚披露用途和飞书群访问范围。默认关闭语音转写及自动转发，和默认开启的 SMS 转发开关**相互独立**。
- 用户可一键暂停转写、关闭飞书发送、删除本次内存会话；发生识别异常、失去授权或电话结束时停止。只在 Mac 在线且电话音频处于活动状态时运行；手机脱离 Mac 时不能实时转写电话。

## 2. 现有可复用的架构

```
Android 电话音频助手 / ADB 会话
        ↓ 16kHz, 单声道, 16-bit PCM, 20ms (320 samples / 640 bytes)
Mac PhoneAudioStream （当前 180 秒测试会话限制）
        ├─ Mac 耳机监听（现有）
        ├─ BlackHole 2ch → ChatGPT Voice（现有实验）
        └─ [新增] CallTranscriptionTap → 音频环形缓冲 → ASR 转写器
                    ↓
              TranscriptAssembler（去重、final/partial、分段时间戳）
                    ↓
              In-memory Transcript / UI（明确标注“对方”）
                    ↓ [用户确认开关]
              FeishuTranscriptForwarder（小批量合并、网络失败显示）
                    ↓
              用户配置的私有飞书机器人
```

如果需要“我方说话”转写，在物理麦克风音频入队前另外建立独立 tap，声道标记为“本机”；若 AI 语音上行，则单独标记为“AI 回答”，不能当成使用者真人。V1 默认只识别对方下行，减少重叠说话、串音、回声和错误归属。

## 3. 转写引擎选择与验证

| 引擎 | 优点 | 风险与验证项 |
|---|---|---|
| Apple Speech / SpeechAnalyzer + SpeechTranscriber | 系统 API；macOS 26 具备新的转写组件，无额外付费服务 | 检查 macOS SDK 的具体 API 与可用语言模型/locale（如 zh-CN），检验本机离线可用性、授权和连续流时延；不假设每个语言/型号都支持 |
| whisper.cpp 本地模型 | 开源、可在 Apple Silicon 本地运行，支持中文，易于离线部署 | 模型下载大小与授权审查、CPU/GPU/ANE 占用、噪声/方言/专业术语准确率、分段重复去重 |

**建议先做本地 whisper.cpp 小模型/中等模型的对照测试**，同时在 macOS 26 上尝试 SpeechTranscriber；选择对普通话、实时性及设备负载更合适的一套。不要直接把 ChatGPT Plus Voice 当作 ASR API。

## 4. 处理管线

1. 在原始 PCM 已解码、但还没有输出到播放器之前，复制只读片段到新的有界环形队列（正常电话链路最高优先级；识别阻塞绝不影响通话音频）。
2. 通过 VAD 或 0.5~1.5 秒静音切分 2~8 秒片段；按实际实验调优，保留 300~500ms 片段重叠提升断句准确率。
3. ASR 返回 `partial` 和 `final` 事件。UI 可显示临时文字，但**只有 final 且去重后的文本才进入飞书待发队列**；含不确定语句时标记低置信度，避免虚构不存在的词。
4. 消息结构示例：`[电话通话转写] 会话A / 00:14–00:20 / 对方：……`。不要附电话号码、设备序列号、Webhooks、IP、原始音频。
5. 按 15~30 秒或一段完整发言合并发送；加会话随机 ID + 片段序号避免重复通知。飞书发送必须独立于 SMS Webhook 设置开关，并默认停止/暂停；仅在用户明示授权后启用。
6. 明确记录计数：PCM 入队帧数、ASR 丢弃帧数、最后识别时间、final 片段数、飞书发送成功/失败次数、发送队列长度；**诊断 ZIP 不包含正文或通话原声**。
7. 断网时只保留短暂的内存队列并设置容量/过期时间，默认不落盘。Mac 关闭或断线则不补发过期通话文本；如未来需要持久化，须另设显式同意的加密存储开关。

## 5. 安全、合规与体验边界

- 音频转写、远端分享/转发均应在知情同意下进行；不同地区对通话录音或转写的法律要求不同。不能假定另一方知道自己被转写。建议在实际通话前口头告知并确认，同时在 Mac 显示显著的“正在转写 / 正在向飞书发送”状态。
- 电话号码、账户信息、短信验证码、银行卡号等敏感内容默认可选本地遮盖；必要时提供“只显示完整文本不自动发送”的安全模式。**不要将 OTP 或个人密码作为电话内容自动转发给群**，除非当事人明确选择且群访问严格受限。
- Webhook 用现有 Mac 钥匙串密钥，但转写 Webhook 单独开关和单独速率限制；日志只保存事件类型、时间戳、数值，不保存文本。
- 最小化存储，添加“结束通话后清除内存文本”选项，默认清除。避免混合电话下行与 ChatGPT 回复造成循环转写/错误标识。
- 目标平台 Mac Apple Silicon + macOS 26；如果用户切换到别的平台或 Android/ADB 无法提取通话音频，须明确退化为“人工录音/导入文件转写”，不虚报自动通话转写。

## 6. 分阶段实现与验收

**阶段 T1（仅本地试验，不转发）：** 用户开始通话且双方同意后，Mac 识别对方下行 16k PCM，显示滚动文字、起止时间和诊断；15 分钟模拟 PCM 测试，检查丢帧与旧电话音频路径回归；注意现有通话会话仍限制 180s，实际验收需单独设计安全的延长策略。

**阶段 T2（可选本地转写+飞书）：** 增加“向飞书发送通话转写”独立同意开关，先支持完整终稿小批量发送，禁用/网络断开不发送，支持手动停止/抹除；验证一个通话只会生成对应会话的片段，不重复推送。

**阶段 T3（上行/双方对话和摘要）：** 区分本人、对方与 AI 说话的来源，处理重叠/换人和自然分段；可在通话结束后由本地模型生成可编辑摘要，先人工审核再发送；不得把 ChatGPT Plus 登录或 Voice 服务当成可直接调用的文字生成 API。

**验收标准：** 通话上下行延迟和丢帧没有明显退化；转写能在中文普通话测试语料上给出可审核的错误率；发往飞书的每个片段能追溯源声道和时间戳；用户不启用时无通话文本送外网；结束后缓冲与计时器释放；验收使用匿名模拟数据而非真实 OTP / 银行资料。
